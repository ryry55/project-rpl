T6: denda 1%/hari plafon 30% + simulasi tanggal (R-03)

Menyelesaikan #7.

Domain
- Kalkulator::hitungDenda: dihitung sekali jalan dari hari_terlambat, bukan
  diakumulasi per hari. Parameter diterima sebagai array primitif, bukan model.
  Titik batas 7/8/30/37/365 benar untuk pokok 1.500.000:
  0, 15.000, 345.000, 450.000, 450.000.
- Kalkulator::plafonDenda, hariDenda, hariHinggaPlafon.
- Kalkulator::persenKeRatusan: persentase diurai dari teks, bukan di-cast ke
  float. 1,15% tidak eksak sebagai float dan bisa meleset Rp 1.
- PenghitungDenda: membaca snapshot tarif_denda_persen/plafon_persen/
  masa_tenggang dari baris tagihan, bukan parameter_denda terkini (R-06 lapis 2).
  Dasar denda = pokok yang dibekukan, bukan sisa; lunas/dibatalkan jadi 0.
- HasilDenda: objek hasil agar layar tidak menghitung ulang aturan.

Waktu
- App\Support\WaktuSistem: satu-satunya sumber "hari ini", singleton,
  di-reset middleware di awal tiap permintaan.
- Middleware SimulasiTanggal: X-Simulasi-Tanggal hanya berlaku bila
  APP_DEMO_MODE=true; format tidak sah diabaikan (bukan 400) supaya demo tidak
  gagal karena salah ketik; mengumumkan X-Simulasi-Dipakai di respons.

API
- GET /tagihan/{id}/denda
- meta { tanggal_acuan, simulasi, demo_mode } di GET /tagihan
- TagihanResource memakai denda sungguhan, bukan placeholder 0
- cors.php exposed_headers supaya header simulasi terbaca JavaScript

Web
- kendali simulasi tanggal di halaman Tagihan
- kolom Denda dan Total di daftar
- panel rincian menjelaskan hari terlambat, plafon, sisa hari ke plafon
- panel rincian ikut disegarkan saat tanggal acuan berubah

Bukti
- 136 tes hijau (992 asersi); 46 tes murni dalam 0,07 detik tanpa basis data
- 23/23 langkah E2E browser; 2 screenshot di docs/uji/
- R-03 selesai di audit ketertelusuran

Dua bug ditemukan tes dan tangkapan layar, keduanya dicatat di audit:
Carbon 3 melempar exception untuk tanggal tidak sah (bukan null), dan panel
rincian tidak ikut disegarkan saat simulasi dibersihkan.
